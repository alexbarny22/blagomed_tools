## Устройство типового проекта

- start.bat — запускает update.py, затем deps.py, затем бота в цикле с перезапуском.
- update.py — сверяет version.txt с GitHub; если там новее — скачивает файлы из manifest.txt.
  Никогда не трогает config.py, логи и start.bat (список PROTECTED).
- manifest.txt — список файлов, которые обновляются автоматически.
- version.txt — версия в формате ГГГГ.ММ.ДД-N (например 2026.11.03-1).
- deps.py — ставит недостающие пакеты.
- config.example.py / config.example.ini — образец настроек. Настоящий config.py с логинами,
  паролями и токенами лежит только локально и в репозиторий не попадает (.gitignore).

## Правила при правке

1. После изменения кода проекта ОБЯЗАТЕЛЬНО подними version.txt этого проекта
   (сегодняшняя дата, N = 1, 2, 3… если за день уже были версии). Иначе на сервере не обновится.
2. Новый файл, который должен приезжать на сервер, — добавь в manifest.txt этой папки.
3. Новый параметр настроек — добавь в config.example.* с понятным комментарием
   и безопасным значением по умолчанию в коде (getattr(config, "X", default)).
4. Никогда не вписывай реальные пароли/токены в файлы репозитория.
5. Если поменялось назначение проекта — обнови строку в корневом README.md.
6. GitHub — источник для автообновления: установки качают файлы из main по version.txt+manifest.txt.
   ⇒ в начале правки сделай `git pull origin main` и сверь состояние папки проекта
     (могут быть свежие чужие правки или более новая version.txt).
   ⇒ в конце правки всегда: `git add`, `git commit`, `git push origin main` —
     иначе автообновление на серверах не сработает и локальная копия разойдётся с main.

## Экономное чтение больших файлов

Файлы > 800 строк (move_bot.py, blagomed_cost.py, render.py, prihod_po_foto/flow.py, engine.py,
direct_report.py, zakaz_postavshiku.py, VK_bot.py) НЕ читай целиком.
Сначала search_files по имени функции/строке ошибки, потом read_file только нужного диапазона.
README.md внутри папки проекта обычно короче и описывает логику — читай его первым.
