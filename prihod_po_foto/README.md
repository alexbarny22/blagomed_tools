# Приход по фото

Telegram-бот: фотографируете накладную поставщика (УПД, ТОРГ-12, накладная, счёт — все страницы),
бот распознаёт её нейросетью, проверяет суммы, находит поставщика по ИНН и товары в 1С и
**создаёт и проводит «Приобретение товаров и услуг»** в 1С:УТ 11.5 (общий склад, ИП Липихин).

## Как пользоваться

1. Пришлите боту все фото накладной (можно альбомом). Лучше отправлять **как файл** (скрепка →
   «Файл»): Telegram не сжимает фото, и мелкие цифры читаются точнее.
2. Нажмите **«Распознать»** — 20–60 секунд.
3. Если товар бот видит впервые — он спросит кнопками, что это у нас в 1С. Выбор **запоминается**
   (для каждого поставщика отдельно), в следующий раз не спросит.
4. Бот покажет итог: строки, суммы, ⚠️ на сомнительных местах. Ошибку исправляете кнопкой
   **«✏️ Исправить строку»** → выбираете строку → «Количество», «Цена», «Сумма», «Другой товар» или
   «Не приходовать» → вводите только число.
5. **«Провести в 1С»** — бот создаст и проведёт поступление и пришлёт его номер.

### Привязка к заказам поставщику
Если у поставщика есть открытые «Заказы поставщику» (как у Гаврюшкина), бот раскладывает строки накладной
по ним — от старых заказов к новым — и заполняет в поступлении колонку «Заказ поставщику».
Уже оприходованное прошлыми поступлениями учитывается; закрытые заказы не трогаются. Если товар есть
в двух заказах, строка делится (например, 20 шт в один заказ и 30 в другой), суммы делятся по количеству.
В итоге перед проведением видно, какая строка в какой заказ легла. Товар, которого нет в открытых заказах
(или привезли больше заказанного), привязывается к открытому заказу, куда легла большая часть поставки
(или к самому свежему) — в итоге это видно как «сверх заказа». ⚠️ будет, только если открытых заказов нет вовсе. Отключить привязку: `USE_ORDERS = False` в config.py.

Заказы читаются из 1С заново на каждой накладной и ещё раз прямо перед проведением — новые и закрытые
заказы бот видит сразу. Цена в накладной сверяется с ценой в заказе: если отличается, строка помечается 💰
с разницей в процентах. В поступление идёт цена из накладной (сколько реально выставил поставщик).

### Таблица сопоставлений (`Сопоставления.xlsx` в папке бота)
Названия у поставщиков часто не совпадают с нашими, а артикулов нет. Поэтому бот ведёт таблицу:
**поставщик → название у поставщика → код у поставщика → наш товар в 1С → код в 1С**.

- Выбрали товар кнопкой — строка добавилась сама. В следующий раз бот узнает товар без вопросов,
  даже если название прочиталось чуть иначе (по коду у поставщика).
- Если названия совсем не похожи, бот спрашивает нейросеть и показывает её вариант первым — с 🤖.
- Таблицу можно заполнить заранее (например, по прайсу поставщика) или исправить в Excel. Наш товар
  ищется по колонке «Код в 1С», а если она пустая — по точному наименованию.
- Кнопка **«📋 Таблица сопоставлений»** внизу экрана — бот пришлёт таблицу. Исправьте её в Excel и просто
  отправьте файл боту (скрепка → Файл) — он заменит таблицу.
- Если таблица открыта в Excel на компьютере бота, новые строки подождут и запишутся, когда файл закроют.

Забыли страницу — просто дошлите фото, бот распознает всё заново.
Внизу экрана всегда есть кнопки: «📋 Таблица сопоставлений», «🔄 Обновить товары из 1С»
(если завели новый товар), «✖ Начать заново». Команды запоминать не нужно.

### Как бот защищается от плохих фото
- Проверяет каждую строку: количество × цена = сумма.
- Сверяет сумму всех строк с итогом документа.
- Замечает пропущенные номера строк (не хватает фото).
- Если первая нейросеть ошиблась — сам пробует следующую из списка и берёт лучший результат.
  Кнопка **«Другой нейросетью»** — перераспознать вручную.
- Не создаёт второе поступление по тому же номеру документа поставщика без вашего подтверждения.

Фото и распознанные данные каждого проведённого документа сохраняются в папку `history`.

## Установка (один раз)

Бот должен работать постоянно, поэтому ставьте его на компьютер, который не выключается —
лучше всего на сам **сервер 1С** (или рабочий ПК, если он включён весь день).
Нужен Python (как для move_bot).

### Шаг 1. Создать бота в Telegram
1. В Telegram найдите **@BotFather**, напишите `/newbot`, придумайте имя (например «Благомед Приход»)
   и адрес (например `blagomed_prihod_bot`).
2. BotFather пришлёт **токен** — длинную строку вида `1234567890:AAH...`. Скопируйте.

### Шаг 2. Скачать бота
1. Создайте папку, например `C:\Боты\prihod_po_foto`.
2. Скачайте в неё с GitHub файлы `start.bat` и `update.py` из папки `prihod_po_foto`
   (открыть файл → кнопка «Download raw file»).
3. Двойной щелчок по **start.bat** — он сам скачает остальные файлы, создаст `config.py` и откроет его
   в Блокноте.

### Шаг 3. Заполнить config.py (откроется в Блокноте)
- `TELEGRAM_TOKEN` — токен из шага 1 (в кавычках).
- `ONEC_USER`, `ONEC_PASSWORD` — тот же логин 1С, что в move_bot.
- `WAREHOUSE` — точное название общего склада, как в 1С.
- `VSELLM_URL` и `VSELLM_KEY` — адрес API и ключ из личного кабинета агрегатора.
- В `MODELS` в поле `"model"` — точные имена моделей (как их узнать — шаг 5).

Сохраните (Ctrl+S) и закройте Блокнот.

### Шаг 4. Открыть боту доступ к документам в 1С (один раз)
Двойной щелчок по **setup_odata_prihod.bat**. Подождите несколько минут (подключение к 1С медленное),
в конце будет «Готово». Уже включённые объекты для других ботов не трогаются.

### Шаг 5. Выбрать нейросеть
1. Двойной щелчок по **test_models.bat**, введите `2`, Enter — появится список моделей агрегатора.
   Скопируйте в `config.py` имена нужных (например с «claude-sonnet» и «gemini-pro»).
2. Положите в папку `test_photos` 3–5 реальных накладных, **включая самые плохие фото**:
   одна накладная = одна папка с её страницами (или один файл, если страница одна).
3. Снова `test_models.bat`, введите `1`. В конце будет итог: какая модель сколько накладных прочитала
   без ошибок. Её поставьте **первой** в списке `MODELS`. В 1С тест ничего не пишет.

### Шаг 6. Запуск
1. Двойной щелчок по **start.bat**. Окно должно оставаться открытым (можно свернуть).
2. Напишите боту в Telegram `/start` — он ответит вашим ID. Впишите его в `ALLOWED_IDS`
   в `config.py` (например `ALLOWED_IDS = [123456789]`; несколько — через запятую),
   закройте окно бота и снова запустите `start.bat`.

Чтобы бот запускался сам после перезагрузки компьютера: Win+R → `shell:startup` → Enter →
в открывшуюся папку положите **ярлык** на `start.bat`.

Обновления: при каждом запуске `start.bat` сам скачивает новую версию с GitHub.
`config.py` и выученные сопоставления (`mapping.json`) при обновлении не трогаются.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «не включён в OData» | Запустить `setup_odata_prihod.bat` |
| «Нет доступа (401)» | Проверить `ONEC_USER` / `ONEC_PASSWORD` в `config.py` |
| «Поставщик не найден в 1С» | Завести контрагента в 1С с этим ИНН, нажать «Найти снова» |
| «записано, но НЕ проведено» | Открыть документ в 1С по номеру, посмотреть причину, провести вручную |
| Все нейросети «ошибка: HTTP 401» | Проверить ключ `VSELLM_KEY` и баланс у агрегатора |
| Бот не отвечает | Посмотреть окно `start.bat` и файл `prihod_bot.log` |

**Как заполняется документ.** Шапка (соглашение, договор, налогообложение) копируется с последнего
проведённого поступления от этого поставщика; если его нет — с любого поступления, а соглашение и договор
подбираются по поставщику. Склад и организация — из `config.py`. Суммы строк берутся из накладной
(с НДС поставщика, то есть сколько реально заплатили), цена = сумма ÷ количество.
Дата поступления — сегодня (в `config.py` можно `DATE_MODE = "document"` — дата накладной).
