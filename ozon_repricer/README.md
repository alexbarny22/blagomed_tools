# ozon_repricer — репрайсер Ozon (цены своих товаров)

Раз в N минут (по умолчанию 30) забирает из Ozon цены, остатки (FBO/FBS/FBP) и фото
всех товаров, пишет их в локальную базу (история для графиков) и по правилам сама
возвращает цену в границы или держит её на уровне удержания. Мин/Макс — границы
**цены селлера** (price, уходит в Ozon); цель удержания — для контролируемой цены
(со скидками продавца или ≈ покупателя). Ограничения: не более 8 изменений одного
товара в сутки и шаг не больше 25% за раз, после изменения — пауза 60 минут.

Правила товара (поле → смысл):
- `mode`: `watch | guard | hold` (только следить / границы / удержание);
- `min_price`, `max_price` — границы цены селлера; `target` — цена удержания;
- `max_strategy`: `0` — не превышать максимум (цена встаёт на макс, статус `hitmax`),
  `1` — строгое удержание: можно выше макс, но не выше `макс × (1 + strict_overshoot_pct/100)`;
- `control_basis`: `''` (как в настройках) | `'seller'` | `'buyer'` — тип контроля для товара;
- `tags`: теги через запятую (фильтры на «Товарах» и «Графиках», массовые +/−);
- `locked` («Под MPSpace»), `hidden` (скрытие из таблиц) — как раньше.

Акции Ozon (этап 2б, версия 2026.11.27-2):
С 19.10.2026 у Ozon «единая предельная цена»: товар участвует в акции, пока цена селлера
не выше требуемой (`max_action_price`), отдельных методов входа/выхода нет. Рекомендации
входа/выхода (`engine.promo_decisions`, `_apply_promo`, `action_manual`, `/api/action/*`)
удалены. Осталось:
- чтение и синхронизация акций (`/v1/actions`, `/v2/actions/products|candidates`,
  `/v2/actions/auto-add/products/list`) с интервалом `actions_interval_min`; таблицы
  `product_actions`, `auto_add`, метка `actions_synced_at`;
- настройка `rules.promo_auto_add`: `''` — не трогать, `'on'` — разрешить автодобавление,
  `'off'` — запретить. Старые колонки `promo_mode/promo_entry/promo_deviation_pct` не удаляются
  (одноразовая миграция в `db.init()`: `promo_mode=1` → `'off'`, `3`+`AUTO` → `'on'`, иначе `''`;
  запись о переносе — в «События»);
- при синхронизации `/v5/product/info/prices` сохраняется `products.auto_add_enabled`
  (поле `auto_add_to_ozon_actions_list_enabled`, 1/0/NULL — нет данных);
- в `_apply_prices` настройка отправляется в `/v1/product/import/prices`, если `promo_auto_add`
  задан и не совпадает с `auto_add_enabled`: при изменении цены в том же запуске — в то же тело
  запроса, иначе вместе с текущими `price/old_price` (цена не меняется). Это НЕ изменение цены:
  журнал с `source='акции: автодобавление'`, паузу/суточный лимит/`guard_against_loops` не трогает.
  Тренировка — только запись «что сделал бы»; «Под MPSpace» — ничего. Ошибка Ozon по полю — в
  журнал, «Требует внимания» (`attention_for`) и предупреждение в «События».
  Повторная отправка настройки автодобавления — не чаще раза в 6 часов на товар; если Ozon принял
  запрос, но `products.auto_add_enabled` после синхронизации так и не совпал с настройкой, после
  2 неудач попытки прекращаются («Требует внимания: Ozon не применяет настройку автодобавления»)
  до изменения настройки пользователем. У товара без цены (`price` пусто/0) автодобавление
  не отправляется, в журнал пишется «нет цены». В тренировке запись «что сделал бы — автодобавление»
  тоже не чаще раза в 6 часов на товар.
- диагностика: при синхронизации участник с `price > max_action_price` даёт одно предупреждение
  в «События» в сутки («Проверка правил Ozon: N товаров… сообщите разработчику»).
- CSV: столбец «Автодобавление в акции (on/off/пусто)» в конце; старые файлы переводятся по
  миграции (если колонки нет, но есть старые столбцы акций), файлы этапа 1 не трогают настройку.
Ошибка при чтении одной акции (в т.ч. разбор JSON) не роняет проверку цен: в «События» пишется
предупреждение, прежние данные этой акции сохраняются; удаляются только акции, которых больше
нет в `/v1/actions` или у которых истёк `date_end`.

Остатки `/v4/product/info/stocks` грузятся в `products.stock_fbo/fbs/fbp/total` при каждой
синхронизации; ошибка получения остатков не ломает проверку цен (только событие-предупреждение).
«Требует внимания» (`attention_for`) — вычисляемый флаг с причинами (границы, цель, акция
с фиксированной ценой, ошибка отправки, остаток 0, красный индекс, автодобавление в акцию
ниже минимума по таблице `auto_add`).

## Прибыль с продажи и безопасный минимум (этап 3, версия 2026.11.24)

- **Себестоимость** — `products.cost` (₽/шт). Заполняется вручную в карточке (`POST /api/cost`),
  массово из Excel (`POST /cost/import`, парсер `app.parse_cost_rows`): формат
  `blagomed_cost.py` («Благомед_себестоимость_*.xlsx», лист «Себестоимость», столбцы
  «Артикул поставщика» + «Себестоимость»; названия ищутся по первой строке) и простой
  файл «Артикул» + «Себестоимость». В файле «Благомеда» значения уже с наценкой ×1.15 —
  делитель `cost_divider` (настройка) применяется при импорте. Отчёт «загружено N,
  не найдено на Ozon: артикулы» — в «Событиях». Если один «Артикул поставщика»
  встречается в файле несколько раз с разной себестоимостью — берётся большая,
  такие артикулы перечисляются в отчёте об импорте.
- **Расходы Ozon** сохраняются из `/v5/product/info/prices` при каждой синхронизации
  без лишних запросов: `acquiring`, `comm_sales_pct_fbo/fbs`, `comm_direct_min/max_fbo/fbs`,
  `comm_mile_fbo/fbs` (колонки `products`). Схема — `engine.cost_scheme(p)`: FBS, если
  остаток только FBS, иначе FBO. Логистика консервативно по максимуму (`_max`).
- **Прибыль** — `engine.profit_of(p, s)`: цена с акциями продавца − комиссия% − логистика −
  эквайринг − налог% − себестоимость; процент от цены с акциями. Ошибки-причины:
  «нет себестоимости», «нет данных Ozon о комиссиях». Разбивка подсказки — `app.profit_tip_text`.
- **Безопасный минимум** — `engine.safe_min_calc(p, s)`:
  `ceil((себестоимость+логистика+последняя миля+эквайринг) / (1 − комиссия% − налог% − маржа%))`;
  `«маржа недостижима»`, если знаменатель ≤ 0. Применение только к полю «Мин» без затирания
  правила — `db.set_min`; по одному (`/api/safe_min/<pid>`) и массово (`/api/safe_min/batch`).
  Товары «Под MPSpace» пропускаются (только показ значения). Считается для цены без скидок акций.
- **Настройки** (вкладка «Настройки» → «Прибыль и безопасный минимум»): `tax_pct`,
  `cost_divider`, `min_margin_pct`.
- **CSV правил**: в конец добавлен столбец «Себестоимость, ₽» (импорт — колонка игнорируется,
  если её нет — старые файлы загружаются).

Запуск на Windows: `1_INSTALL.bat` (один раз, ставит Python-окружение) → ярлык
«Repricer Ozon» (или `2_START.bat`). Интерфейс: http://127.0.0.1:8765.
Подробная инструкция для пользователя — в `README.txt`.

## Что в папке
| Файл | Назначение |
|---|---|
| `app.py` | Flask-интерфейс и API |
| `core/ozon.py` | Клиент Ozon Seller API (чтение/запись цен, остатки), режим `OZON_MOCK=1` для проверки без ключей |
| `core/db.py` | SQLite-база: товары, правила, история цен, журнал, настройки; миграции через `ALTER TABLE` в `init()` |
| `core/engine.py` | Логика: синхронизация, правила, удержание, стратегия при максимуме, «требует внимания» |
| `templates/`, `static/` | Интерфейс, графики, фото товаров |
| `update.py` | Автообновление из этой папки GitHub (понимает подпапки) |
| `version.txt`, `manifest.txt` | Номер версии и список файлов для автообновления |

## Автообновление
При каждом запуске (ярлык, автозапуск, `2_START.bat`) `app.py` вызывает `update.py`:
сверяет `version.txt` с GitHub и, если версия новее, скачивает файлы из `manifest.txt`
и перезапускается уже новой версией. `data/` и `venv/` не трогаются никогда,
`.bat`-файлы не обновляются. Нет связи с GitHub — запускается текущая версия.

**Чтобы выпустить обновление:** поменять файлы, при добавлении нового файла — дописать его
в `manifest.txt`, и обязательно увеличить номер в `version.txt`.

## Секреты
Client-Id и Api-Key Ozon вводятся в интерфейсе и хранятся только в локальной
`data/repricer.db` — в репозиторий они не попадают (`data/`, `venv/` в `.gitignore`).
При установке папка `venv/` создаётся сама.
