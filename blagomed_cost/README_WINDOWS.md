# Windows 11: установка и запуск «Себестоимость МП»

Веб-интерфейс этапа 7: вход по логину, загрузка отчётов WB/Ozon, расчёт,
карточки товаров, вес ППУ и доп. расходы с датами, ручные цены, проблемы,
история запусков и скачивание XLSX. Рабочая БД не создаётся и не меняется
без явного действия пользователя.

## Требования

- Windows 11, Python 3.10+ (проверено на 3.14), доступ в интернет только
  для `pip install`.
- 1С УТ 11.5 — по желанию. Без 1С доступны ручные цены и снимки прошлых
  расчётов; приложение работает и показывает причину недоступности 1С.
- Права на запись в каталог установки (для `data`, `uploads`, `output`,
  `logs`, `backup`).

## Каталог установки

Рекомендуемая раскладка:

```text
C:\Blagomed\SebestoimostMP\
  app\  migrations\  tools\  tests\  legacy\
  config.example.ini
  install.bat  start.bat  stop.bat  env-check.bat
  data\      (БД, секрет сессий, история JSON, uploads.json)
  uploads\   (копии принятых XLSX)
  output\    (результаты расчёта)
  logs\      (web.log, server.out)
  backup\    (копии БД перед миграцией)
```

`start.bat`, `stop.bat` и `env-check.bat` по умолчанию работают с каталогом,
в котором лежит сам BAT. Автоматического переключения на
`C:\Blagomed\SebestoimostMP` или другую установленную копию нет. Чтобы
запустить приложение из другого каталога, задайте переменную явно:

```bat
set BLAGOMED_BASE=D:\Blagomed\SebestoimostMP
start.bat
```

## Установка

Скопируйте проект в `C:\Blagomed\SebestoimostMP` и запустите `install.bat`
из этого каталога. Он создаёт `venv`, ставит зависимости из
`requirements.txt`, при отсутствии копирует `config.example.ini` в
`config.ini` и не создаёт базу данных.

Те же шаги вручную:

```bat
cd /d C:\Blagomed\SebestoimostMP
py -3 -m venv venv
venv\Scripts\python.exe -m pip install --upgrade pip
venv\Scripts\pip.exe install -r requirements.txt
copy config.example.ini config.ini
```

В `config.ini`:

1. `[web] host = 127.0.0.1` — только этот компьютер; `0.0.0.0` — доступ
   с другой машины локальной сети (обязателен вход, см. ниже).
2. `[auth] user` — логин; `pass_hash` — хэш, создать командой:

```bat
venv\Scripts\python.exe tools\hash_password.py "надёжный-пароль"
```

Строку целиком вставить в `pass_hash`. Пароль в открытом виде не хранить.
Без заполненного `[auth]` вход закрыт и приложение не даёт работать.

3. `[1C] mode/server/base/user/password` — доступ только на чтение. Пароль
   1С остаётся в `config.ini` (файл в git не попадает).
4. `[Цены]` и `[Расчёт]` — вид цены, поставщик и справочные начальные
   значения. Рабочие значения ведутся в БД с датами; новая база сразу
   создаётся с ППУ 405 ₽/кг, наценкой **15%** и порогом 10% на 2026-07-01.
   В `[Расчёт]` наценка задаётся в процентах: `margin_pct = 15` (не `0.15`).

## Первый запуск и база

```bat
env-check.bat
start.bat
```

Открыть `http://127.0.0.1:8085` (порт из `config.ini`), войти. На странице
«База данных»:

- «Создать БД» — новая SQLite штатными миграциями; в неё сразу записываются
  начальные параметры расчёта 405 ₽/кг, 15% и порог 10%;
- «Перенести legacy» — только при наличии `legacy\wb_catalog.json` и
  `legacy\cost_history.json`; без них миграция останавливается, БД не
  повреждается;
- «Применить миграции» — только после явного подтверждения; перед
  изменением схемы создаётся копия в `backup\`.

Существующая БД никогда не перезаписывается автоматически. Если порт занят,
`start.bat` сообщает об этом и не запускает второй экземпляр. Если сервер уже
запущен из этого каталога, `start.bat` показывает его PID и завершается без
второго процесса.

## Ежедневная работа

1. «Расчёт» → загрузить один или два XLSX (WB и/или Ozon) одним запросом.
2. Выбрать дату и режим цен: 1С, снимок (историческая цена) или без 1С.
3. «Рассчитать» → статус и результаты; скачать XLSX можно после
   подтверждения, меняются только ячейки себестоимости.
4. «Проблемы» — нерешённые строки; ручная цена или «оставить нерешённым»
   (решение пишется в аудит). Остальные строки не блокируются.
5. «Товары»/«Расходы» — вес ППУ, доп. расходы и параметры расчёта
   (ставка ППУ, наценка) с датой начала; история сохраняется.
6. «История» — запуски и файлы любого запуска.

## Доступ с другой машины

По умолчанию сервер слушает только `127.0.0.1`. Для проверки с другой
машины:

1. В `config.ini` укажите `host = 0.0.0.0`, перезапустите сервер.
2. Разрешите входящий TCP-порт (по умолчанию 8085) в брандмауэре Windows
   только для доверенной подсети.
3. Откройте `http://<IP-сервера>:8085`, войдите по логину и паролю.

Передача идёт по HTTP без TLS: используйте только доверенную локальную
сеть/VPN. Для постоянной работы с других машин поставьте обратный прокси
с HTTPS. Без входа недоступны все разделы, кроме `/login` и `/healthz`.

## Остановка и диагностика

```bat
stop.bat
env-check.bat
venv\Scripts\python.exe tools\web_control.py status
```

- PID: `data\web.pid`; журнал: `logs\server.out`, `logs\web.log`.
- `stop.bat` останавливает только процесс из PID-файла после проверки
  командной строки.
- Если порт занят, остановите старый процесс или измените `port`.

## Проверка качества

```bat
venv\Scripts\python.exe -m pytest -q
venv\Scripts\python.exe tools\e2e_web.py
```

E2E работает на копии подготовленной БД в `output\e2e_web`, не создаёт и
не изменяет рабочую `data\cost.db`, проверяет хэши исходных XLSX. Для E2E
нужны исходные отчёты в `input\` (пути можно задать `--wb` и `--ozon`).

## Ограничения текущего MVP

- 1С GUID не редактируется вручную: идентификатор только читается из 1С;
  неоднозначные сопоставления выводятся в «Проблемы» (правило этапа 7).
- Нет встроенного HTTPS, ограничения попыток входа и CSRF-токенов;
  интерфейс рассчитан на доверенную сеть. Формы используют cookie
  `HttpOnly` + `SameSite=Lax`.
- Дашборд этапа 8 (графики) в этот MVP не входит.
- Импорт MPSPACE принимает только `.xlsx` и форматы WB/Ozon; исходники не
  изменяются.

## Резервное копирование

Остановите сервер, скопируйте `data\cost.db` и каталог `data\history\`.
Перед миграциями копия создаётся автоматически в `backup\`. Восстановление:
вернуть файл БД при остановленном сервере и проверить «База данных» →
целостность.
