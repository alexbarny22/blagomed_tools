# Себестоимость МП

Расчёт себестоимости товаров на Wildberries и Ozon для Благомед.

Закупочные цены берутся из 1С УТ 11.5 (только чтение). К цене добавляется стоимость
наполнителя (вес ППУ × цена ППУ за кг + дополнительные расходы, вводимые вручную:
поролон, упаковка и т.п.), затем ко всему применяется наценка (сейчас 15% — аренда,
зарплата, свет, ГСМ, прочие расходы). Себестоимость единая для OZON и WB.

Сопоставление артикулов МП ↔ 1С берётся из отчётов MPSPACE (Ozon и WB), которые
загружаются вручную через веб-интерфейс.

## Структура

- `app/core/` — расчёт, работа с 1С, сопоставление, отчёты, БД
- `app/web/` — Flask: веб-интерфейс, дашборд
- `migrations/` — нумерованные миграции SQLite
- `tools/` — служебные скрипты (inspect_xlsx, migrate_legacy, hash_password)
- `tests/` — pytest; фикстуры `tests/fixtures/` (синтетические, без коммерческих данных)
- `legacy/` — старый бот `blagomed_cost.py` без изменений (для справки и сверки);
  сюда же кладутся локальные файлы-память (см. ниже)
- `docs/` — служебная документация (план переноса `CLINE_PROMPT.md`, контекст `CONTEXT.md`)
- `input/` — сюда кладутся отчёты MPSPACE (не в git)
- `output/` — результаты расчёта (не в git)

## Дополнительные расходы (версионирование)

Статьи доп. расходов (поролон, упаковка и т.п.) ведутся по периодам: новая запись
той же статьи у товара с даты `valid_from` **заменяет** предыдущую, разные статьи
суммируются. Закрытая запись (`valid_to <= дата расчёта`) не возобновляется —
более ранние записи со свободным `valid_to` не возвращаются. Период
`valid_to <= valid_from` считается ошибкой данных: расчёт отказывается с
понятным сообщением, не подставляя «тихий» расход. Расчётное ядро только
читает строки `extras`, история периодов сохраняется.

## Установка и настройка нового модуля

1. `python -m venv venv`, затем `venv\Scripts\pip install -r requirements.txt`
2. Скопировать `config.example.ini` в `config.ini`, заполнить данные 1С, логин веб-интерфейса и хэш пароля
3. Пароль для веб-интерфейса: `python tools/hash_password.py <пароль>` → вставить строку в `[auth] pass_hash`
4. Создать БД и перенести данные старого бота: страница «База данных» → «Создать БД», затем «Перенести legacy»
5. Запуск: `python -m app.web.server` (или `start.bat` на Windows, см. `README_WINDOWS.md`)

Вход в интерфейс обязателен: без заполненного `[auth]` все разделы закрыты.
Подробная установка, `start.bat`/`stop.bat`/`env-check.bat`, доступ с другой
машины и ограничения — в `README_WINDOWS.md`.

## Тесты

`pytest` работает на синтетических фикстурах `tests/fixtures/` и не требует локальных
файлов (воспроизводим на чистом клоне). Проверка реального переноса 77 товаров —
`tests/test_migration_real.py`: выполняется только при наличии `legacy/wb_catalog.json`
и `legacy/cost_history.json`, иначе модуль пропускается.

## legacy/ — старый бот `blagomed_cost.py`

> **Восстановлено из переписки (01.11.2026)** — чаты «Формирование прайса с закупочными ценами»
> (май 2026) и «Синхронизация артикулов WB при добавлении новых позиций» (июнь 2026).
> Повторены все правки до финальной версии. Файл перенесён в `legacy/` без изменений
> и сохраняется для справки и сверки с новым модулем.

### Что делает
Раз в месяц формирует два xlsx: `себестоимость_контроль_ГГГГ_ММ.xlsx` (детальный расчёт,
подсветка резких изменений ±10%) и `Благомед_себестоимость_ГГГГ_ММ.xlsx` (для загрузки
в сервис аналитики). Формула: `floor((закуп + вес_г/1000 × 405 + доп.расходы) × 1.15)`.

### Откуда цены
1. **1С (основной режим, COM)** — регистр «Цены номенклатуры поставщиков», вид «Закупочная»,
   поставщик ГАВРЮШКИН; дубли схлопываются по последнему периоду. Добор — регистр
   «Цены номенклатуры», затем цена последнего поступления.
2. **PDF (резервный)** — `отчет.pdf` из 1С в папке скрипта; из PDF всегда дополняются веса.
3. `FIXED_COSTS` в скрипте — 20 позиций другого поставщика.

### Локальные файлы (не в git)
Перед `python tools/migrate_legacy.py` скопировать из папки работающего старого бота в `legacy/`:
- `legacy/wb_catalog.json` — список позиций (артикул WB ↔ поставщика; 76 позиций).
- `legacy/cost_history.json` — прошлая себестоимость (81 запись) для алертов и переноса.
Без этих файлов миграция останавливается с понятной ошибкой: БД не создаётся,
существующая не изменяется (защита от потери данных и «фиктивного» каталога).
- `weights.json` — веса, г (15 позиций); лежит в git (корень и `legacy/`).
- `config.ini` — создаётся при первом запуске; сервер (лучше IP), база, логин, пароль 1С.

### Установка старого бота (только для сверки)
`pip install pdfplumber openpyxl pywin32`, двойной клик по `legacy/blagomed_cost.py`.
Для COM: разрядность Python = разрядности 1С, зарегистрированная `comcntr.dll`.
