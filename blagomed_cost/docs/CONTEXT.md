## 1С: правила сопоставления и источника цены (контрольная доработка)
- Приоритет: GUID → наименование → артикул-подсказка. GUID первичен даже при
  изменённом артикуле; неверный GUID при совпавшем артикуле → NOT_FOUND.
- Несколько разных кандидатов с одним GUID (разные цены/поставщики) → AMBIGUOUS.
- Совпадение ТОЛЬКО по артикулу → NEEDS_CONFIRM (не OK), цена приложена, не объявлена.
- merge_odata_guid (цена COM ↔ GUID OData): равные GUID → объединение (GUID первичен даже
  при разном артикуле); РАЗНЫЕ GUID → AMBIGUOUS, цена не допускается; GUID только в OData →
  связывание по наименованию+артикулу; только артикул → NEEDS_CONFIRM. Не-подтверждение ≠ OK.
- Источник цены (порядок как в старом боте): exact (вид+поставщик) → вид+владелец → vid_only →
  any → fallback_register («Цены номенклатуры»). Не-exact → NEEDS_CONFIRM. Сохраняется:
  регистр, вид цены, поставщик, дата, цена, source_status.
- Точность цены (Decimal) полная: COM → str(price) → JSON → Decimal. Цена None не
  заменяется нулём; ошибки соединения → CONNECT_ERROR/TIMEOUT/AUTH, не NOT_FOUND.
