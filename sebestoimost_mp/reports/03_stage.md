**Статус: PASS**

## Что сделано

- `app/calc.py` — расчётное ядро, перенесено из проверенной реализации `blagomed_cost` (ТЗ §7): формула `floor((цена + вес_г/1000 × ППУ + Σ доп.расходов) × (1 + наценка/100))`, Decimal + ROUND_FLOOR, выборки «на дату», None ≠ 0 для цены.
- `app/calc_run.py` (новый) — прогон расчёта: запись `runs`/`run_items`, статусы ok/problem, ошибки `CalcError` → проблемные позиции с понятными сообщениями, один commit/rollback.
- `app/web/routes.py` — POST `/calc` (прогон по последним загрузкам), `/download/<mp>` берёт цены из последнего прогона (не считает на лету), `/products` (ручная цена, вес ППУ, переключение режима цены), `/expenses` (настройки ППУ/наценка с valid_from, виды расходов, доп.расходы с периодом и запретом valid_to <= valid_from).
- Шаблоны: `base.html` (рабочая навигация), `index.html` (загрузка, расчёт, сводка последнего прогона, скачивание), `products.html`, `expenses.html`.
- `app/__init__.py` — `init_db` при старте приложения (БД создаётся, существующая не перезаписывается).
- Тесты: `test_calc.py` (11), `test_calc_run.py` (8); обновлён `test_excel_io.py::test_download_route` под контракт «скачивание после расчёта». Всего 31 тест зелёный.
